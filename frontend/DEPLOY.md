# Deploying the Tunakula site (one host, three routes)

Every front-facing surface ships as **one static site**:

| Route | Page | Source |
|---|---|---|
| `/` | Landing | `frontend/landing/landing.html` |
| `/blog` · `/blog/<post>` | Blog + 12 posts | `frontend/blog/` |
| `/pro` | Partner dashboard | `frontend/partner-dashboard/dashboard.html` |
| `/pwa/*`, `/fonts.css`, `/manifest.webmanifest`, `/sw.js` | Shared kit | assembled |

## Build

```bash
pnpm build:blog   # regenerate blog HTML from the corpus (needs `marked`)
pnpm build:site   # assemble everything into frontend/dist/
```

`build:site` (`frontend/build.mjs`) copies each surface into `frontend/dist/`,
rewrites asset references to absolute paths (so every route resolves with or
without a trailing slash), and emits the host configs, `robots.txt`, a unified
`sitemap.xml`, and a branded `404.html`. `frontend/dist/` is git-ignored — it
is a build artifact, regenerated by the command above.

## Host it (pick one)

**Netlify / Cloudflare Pages** — connect the repo; `netlify.toml` sets
`command = node frontend/build.mjs`, `publish = frontend/dist`. The generated
`dist/_redirects` handles `/pro`, `/blog`, pretty article URLs and the 404.

**Vercel** — `vercel.json` sets the build command, output dir, `cleanUrls`
and the `/pro` · `/blog` rewrites.

**Apache / cPanel (the cd.tunakula.com family)** — run the build locally, then
upload the **contents of `frontend/dist/`** to the web root (or a subdomain
docroot). The generated `dist/.htaccess` handles pretty blog URLs, `/pro`,
`/blog` and the 404. No build step needed on the server.

## Before going live — set the real IDs (no code change to the pages)

- **WhatsApp number** — SINGLE source of truth: set `WA_NUMBER` in
  `frontend/site.config.mjs` (digits only, no `+`), then
  `pnpm build:blog && pnpm build:site`. The build swaps it across the
  landing, every blog page, and the dashboard automatically — one edit does
  the whole site. (Today it's the +44 pilot line; a local +243 is D-1.)
- **Analytics** (Meta Pixel + Google tag): fill `frontend/pwa/analytics.config.js`.
- **Blog view counter**: point `frontend/pwa/views.config.js` at the deployed
  `@nzela/views` service. Left empty, the counter stays inert (no errors).

All three live in the shared `/pwa` kit, so one edit applies site-wide.

## Verify locally

```bash
node frontend/build.mjs
npx serve frontend/dist    # or any static server rooted at dist/
# open http://localhost:3000/  ·  /blog  ·  /pro
```
